## Highlights

- **Legacy control-plane upgrade compatibility** — The unified chart now
  handles the remaining PostgreSQL schema, encryption-key, configuration, and
  service-auth compatibility required for direct 6.3 upgrades.
- **Explicit external PostgreSQL TLS modes** — The unified chart supports
  `tls.sslMode=require|verify-full` through
  `externalDependencies.postgresql.tls.sslMode`. Use `verify-full` with a CA
  Secret whenever trust material is available; `require` encrypts transport
  without authenticating the server.

## Helm Charts

- **Legacy MEK encoding accepted**: MEK parsing accepts legacy
  standard-alphabet, unpadded base64 in an inner JWK `k` value and normalizes it
  to the canonical URL-safe representation in memory.
- **Isolated empty identity cleanup**: The users backfill automatically removes
  the isolated empty profile/user pair. It still fails closed when an empty
  identity is referenced by any persistent workload, credential, key, role, or
  access-token row.
- **Historical role foreign keys removed idempotently**: The user-role migration
  removes either historical role foreign-key name, `fk_user_roles_role` or
  `user_roles_role_name_fkey`, and remains safe to rerun.
- **Legacy database configuration retired**: The migration removes
  `SERVICE.service_cluster`, `service_cluster_namespace`, `service_url`,
  `user_data_path`, `user_dataset_path`, `workflow_backends`, and
  `workflow_start_timeout`; `WORKFLOW.credential_validation_enabled`,
  `default_workflow_backend`, `exec_port_config`, and `workflow_alert`; and
  retires every `DATASET` row. Operators must configure the applicable 6.4
  destinations before enabling the cleanup migration.
- **Opt-in service-auth copy with retry attempts**: The temporary migration
  copies and validates an existing database-backed service identity without
  creating or rotating it. Disable the migration after success and increment
  `secrets.serviceAuth.migration.attempt` only when retrying a failed or
  interrupted hook.
