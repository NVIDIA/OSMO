## Highlights

- **Unified OSMO Helm chart** — One `osmo` chart replaces the legacy `service` and `backend-operator` charts, with quickstart, self-contained, single-plane, and split-plane profiles and optional embedded PostgreSQL, Valkey, RustFS, and Dex.
- **Self-hosted MCP server** — AI agents can list pools and resources, submit and manage workflows, and inspect tasks through an authenticated MCP endpoint served at `/mcp`.
- **Workflow labels** — Attach `key: value` labels to workflows, filter by them in the CLI and UI, stamp them onto task pods, and have admins require or validate them through policy.
- **ConfigMap-only configuration** — Service configuration now lives only in the chart's ConfigMap; database-stored configs and the config write and history commands are gone.
- **Dataset feature removed** — `dataset:` inputs and outputs, `osmo dataset`, and `osmo bucket` are removed in favor of `url:` inputs and outputs on object storage.
- **PKCE browser login** — `osmo login` now uses the OAuth authorization code flow with PKCE by default.

## Breaking Changes

- **Legacy charts replaced by the unified chart**: The `osmo` chart replaces the `service` and `backend-operator` charts. Converters in `deployments/upgrades/service_to_osmo_chart/` translate existing values files; follow the [6.3 to 6.4 upgrade guide](https://github.com/NVIDIA/OSMO/blob/main/deployments/upgrades/6_3_to_6_4_upgrade.md). Only upgrades from 6.3 are supported. (#1365, #1373, #1379, #1402, #1442)
- **Database-managed configs removed**: Service configuration is read only from the chart ConfigMap, and chart configuration is now mandatory. Legacy ConfigMap role actions that are no longer supported are rejected. (#1361)
- **Config CLI is read-only**: `osmo config` keeps only `show`. The `set`, `update`, `delete`, `list`, `history`, `rollback`, `diff`, and `tag` commands and the stored configuration history are removed. (#1375, #1423)
- **Workflow tag commands removed**: The retired workflow tag commands are removed from the CLI. (#1377)
- **Datasets removed**: Workflows that use `dataset:` or `update_dataset:` inputs or outputs are rejected at submission. The `osmo dataset` and `osmo bucket` commands, the dataset pages in the UI, the dataset bucket API, dataset config, and the profile default bucket are removed. Use `url:` inputs and outputs instead; the cookbook examples now take `--set storage_url=...`. (#909, #1083, #1089, #1093, #1094, #1119, #1120, #1121, #1126, #1140)
- **quick-start chart removed**: Use the unified chart's quickstart profile, now the default values, which needs only an image-pull Secret. See [Quickstart Deployment](https://nvidia.github.io/OSMO/deployment_guide/appendix/deploy_local.html). (#986, #1332, #1349, #1354)
- **No unauthenticated mode in the unified chart**: The chart no longer supports the insecure unauthenticated or default-identity mode. Embedded Dex is the default identity provider for development installs; see [Migrating to Embedded Dex](https://nvidia.github.io/OSMO/deployment_guide/appendix/authentication/migrating_to_embedded_dex.html). (#1368)
- **Deployment scripts consolidated**: `deploy-osmo-minimal.sh` and the MicroK8s entrypoints are removed. `deploy-osmo.sh` and the new `deploy-osmo-single-plane.sh` install through the unified chart. (#1403)
- **PKCE is the default login method**: `osmo login` opens a browser for the authorization code flow with PKCE. Use `--method code` for device authorization. (#1269)
- **Admin bootstrap token expires**: The default admin bootstrap token now has a lifetime capped at seven days and must be reissued explicitly once it expires. (#1437, #1452)
- **Service and backend credentials move to Kubernetes Secrets**: The service auth identity is stored in a Kubernetes Secret and migrated from PostgreSQL on upgrade. Backend bootstrap tokens and MEKs are read from Kubernetes Secrets, and MEK rotation runs through a lifecycle Job. (#1275, #1307, #1337)

## Helm Charts and Deployment

- **Deployment profiles**: The unified chart ships quickstart, self-contained, single-plane, split-plane control, and split-plane compute profiles. Compute-only installs need only `compute.backendName`. See [Self-contained Deployment](https://nvidia.github.io/OSMO/deployment_guide/appendix/deploy_self_contained.html) and [Single-plane Deployment](https://nvidia.github.io/OSMO/deployment_guide/appendix/deploy_single_plane.html). (#1316, #1336, #1345, #1354)
- **Embedded dependencies**: Optional embedded Valkey, PostgreSQL, RustFS object storage, and memory-backed Dex for installs without external services. (#1286, #1305, #1313, #1368)
- **Chart conventions**: Ingress, HTTPRoute, gateway Service exposure, autoscaling, PodDisruptionBudgets, and values schema validation follow standard chart conventions. (#1293)
- **Kubernetes-native Secrets**: The chart references existing Secrets or generates them, and a single sequenced bootstrap Job sets up service auth, identity, and credentials on fresh installs. (#1294, #1353, #1355, #1414)
- **Credential rotation without restart**: Services poll mounted credentials every 30 seconds and pick up rotated values without a restart, keeping the last valid set if a rotation is invalid. (#1378)
- **ConfigMap reloads update backends**: Reloading the ConfigMap now applies backend side effects such as pod template and queue changes. (#1155)
- **Separate router addresses**: Internal and client-facing router addresses are configured separately and default by deployment topology. (#1453)
- **Gateway rate limiting**: The gateway supports rate limiting for authenticated requests. (#1160)
- **PostgreSQL SSL mode**: PostgreSQL SSL mode is set explicitly, and legacy unpadded base64 MEKs are accepted. (#1379)
- **Kubernetes 1.28 and CRI-O**: Compute clusters on Kubernetes 1.28 and CRI-O runtimes are supported. (#1376)
- **Backend logs to stdout**: Backend components stream logs to stdout instead of writing log files, and agent file log retention is bounded. (#1195, #1197, #1203)
- **Faster startup**: Service startup no longer replaces the PostgreSQL JSON merge function each time. (#1439)
- **Smaller images**: Container images drop duplicate Python runtime layers. (#1322, #1327, #1339)
- **Cloud examples**: Adds an Azure single-plane example and AWS single-plane provisioning. The Azure scripts gain `--with-nfs-storage` for an optional Premium FileStorage account, honor `TF_GPU_COUNT`, accept `gpu_driver=None`, parse GPU quota SKUs correctly, and pin a supported AKS version. (#1035, #1037, #1068, #1122, #1167, #1356, #1403)

## Workflow Labels

- **Labels in the workflow spec**: Workflows accept immutable `key: value` labels that are stored with the workflow and stamped onto task pods. System labels take precedence. Admins can namespace pod labels with `labels_config.pod_label_prefix`. See [Workflow Labels](https://nvidia.github.io/OSMO/deployment_guide/advanced_config/workflow_labels.html). (#1216, #1219, #1221, #1259)
- **Label policy**: `labels_config` lets admins require or validate labels in `warn` or `enforce` mode, with an optional `assert_message`. Policy runs on submit, resubmit, restart, and validate, and results are counted in `osmo_label_validation_total`. (#1220, #1223)
- **CLI support**: `osmo workflow submit`, `osmo workflow validate`, and `osmo app submit` take `--label KEY=VALUE`. `osmo workflow list` filters with `--label` and `--no-label`, supports globs, and shows a Labels column. Policy warnings print as `WARNING` lines. Label values that start with a hyphen are parsed consistently. (#1224, #1225, #1381)
- **UI support**: The workflows list has a Labels column and label filter chips. Workflow details show labels and policy warnings, and the submit and resubmit forms include a label editor. URLs in warning and error messages are clickable. (#1227, #1272)
- **Metrics dimensions**: `osmo_tasks_count` gains bounded label dimensions, and the gauge now counts tasks correctly. (#1226)

## MCP Server

- **Self-hosted MCP service**: Adds an MCP server with tools for pools, resources, workflows, tasks, apps, credentials, and profiles, including `osmo_list_tasks` and workflow label support. See [MCP setup for users](https://nvidia.github.io/OSMO/user_guide/getting_started/mcp.html) and the [MCP tool reference](https://nvidia.github.io/OSMO/user_guide/appendix/mcp/index.html). (#1271, #1285, #1311, #1397)
- **OIDC authentication**: MCP authenticates through FastMCP's OIDC proxy, so clients only need the endpoint URL. Deployers set four values: the resource URL, OIDC configuration URL, client ID, and a Secret with a client secret of at least 32 characters. Register `{origin}/mcp/auth/callback` as the redirect URI. See [MCP deployment](https://nvidia.github.io/OSMO/deployment_guide/advanced_config/mcp.html). (#1300, #1306, #1328, #1350)
- **Unified chart integration**: MCP deploys from the unified chart, runs multiple replicas on OSMO's Redis, and is on by default in the embedded Dex quickstart. Unknown legacy `--config` keys fail at startup. (#1329, #1360, #1390, #1410)
- **MCP fixes**: Fixes private-CA TLS trust, IPv6 Valkey URLs, and readiness checks. Registry errors keep their error codes in MCP submit, validate, and restart responses. (#1366, #1394)

## CLI

- **Clear registry errors**: Workflow submission reports a missing image tag, a registry rate limit, or a registry outage as such instead of asking for credentials, and keeps the workflow ID on every error. (#1366)
- **HTTP error status preserved**: Workflow commands report the service's HTTP status instead of a blank or generic error. (#1372)
- **Empty app files**: Submitting an app with an empty `files` section now fails with an error. (#1380)
- **Repeatable set flags**: `--set`, `--set-string`, and `--set-env` can be passed more than once, and the values accumulate instead of the last flag winning. (#1192)
- **Path-scoped registry credentials**: Registry credentials can be scoped to a repository path. (#1109)
- **Rsync upload paths**: Fixes rsync upload path handling and bundles rsync v0.3.4. (#1213)
- **Profile token expiry**: `osmo profile` shows the expiry for Secret-backed bootstrap credentials. (#1436)
- **CLI fixes**: Fixes template block detection, trims line endings from credential payload files, and fixes the malformed credential docs table. (#1118, #1209, #1249)

## Web UI

- **Log search in context**: Log search results show the surrounding lines. (#1309)
- **Workflow spec links**: Workflow spec links go through the UI proxy and open in the browser instead of downloading. (#1051, #1450)
- **Shared pool capacity**: Fixes capacity usage shown for shared pools. (#1252)

## Workflows

- **Platform-provided host mounts**: Mounts already provided by the pod template, such as `/dev/shm`, are rejected at submission instead of leaving the workflow stuck in PENDING. No-retry task failures now finalize the workflow correctly. (#1055)
- **Log stream cleanup**: The service releases the Redis log reader when a client disconnects. (#1317)
- **Faster queries**: Username resolution and recent task metrics queries are faster, the latter with a new index. (#1314, #1320)
- **Resource and storage fixes**: Fixes duplicate resource name lookups and normalizes empty S3 validation endpoints. (#1211, #1222)

## Authentication and Authorization

- **Pool-scoped authorization**: Pool-scoped roles now apply to requests that address workflows by UUID and to plugin configs. (#1461)
- **Escaped slashes rejected**: The gateway rejects request paths with escaped slashes. (#1178)
- **Service account roles**: ConfigMap role validation covers service accounts, and role assignments are revoked when the role is deleted. (#1326)
- **Role claim sanitization**: The gateway sanitizes role claims before forwarding them in identity headers. (#1300)

## Agent Skills

- **osmo-user skill**: Renamed from `osmo-agent`. Adds an eval suite, a full CLI option reference, and retry and login guidance, and routes requests through MCP when available or the CLI otherwise. (#1059, #1075, #1324, #1371, #1383)
- **osmo-admin skill**: Adds a skill for administering OSMO deployments. (#1071, #1432, #1433)

## Bug Fixes

- **Security updates**: Patches high-severity findings in Next.js, source-map-js, Python dependencies, and container images. (#1323, #1444, #1448)
- **Structured log fields**: JSON service logs include `user_id`, `job_id`, and `status_code`. (#1005)
